# 03 · 接模型

> 基于 `deepseek-ai/deepseek-harness` v0.1.0-rc.5（commit `47f9438`），2026-08-14 核对。本章只讲"把模型配上去"：填 key、加厂商、接自建网关、凭据落到哪个文件、默认模型在哪改、不同用途能不能各用一个模型。写 LLM 适配器只给最小形状与出处，不展开。

**读完这章你会**：

- 在 Web UI 的 Settings → Models 存下 DeepSeek key，并说清它落到磁盘上的哪个文件
- 手写 `settings.yaml` 接一个 OpenAI 兼容的公司网关或本地服务
- 说清 shell 环境、`.credentials.yaml`、两个 `.env` 四层谁压谁，以及为什么它跟普通配置的优先级链不是同一条
- 改掉全局默认模型，并解释为什么老会话不跟着变
- 给会话标题、压缩、子 agent 各挂一个更便宜的模型

先约定三个词。**route（提供方路由）**：一个厂商接入点的名字，如 `deepseek-official`、`anthropic`、`acme-gateway`，发请求时用 `provider: <route>` 指名它。**profile（提供方档案）**：`settings.yaml` 里描述这条 route 的那一小块配置（端点、协议、模型表、凭据引用）——注意它和 `dsh --profile <name>` 那个"启动 profile"是两回事，只是撞名。**seam（接缝）**：一类能力的统一入口，比如凭据 seam `ctx.credentials`，插件只对着入口编程，背后换实现不影响调用方。

## 1. 第一个 key：Settings → Models

Web UI 起来之后（`npx @deepseek-ai/dsh web`，见第 01 章），打开 **设置 → 模型**（Settings → Models）。DeepSeek 卡片的主字段只有一个 API key 输入框，填进去保存即可（`docs/user/guide/providers.md:9`）；`baseURL` 和模型列表在折叠的「自定义设置」里（`packages/client/ui-settings-models/README.md:7`）。模型变更在**下一次请求**生效，不需要重启服务器（`docs/user/guide/providers.md:5`）。

保存那一下发生了三件事：

| 动作 | 落点 | 出处 |
|---|---|---|
| 密钥本身 | `$DSH_HOME/.credentials.yaml`，只写不回读；页面拿到的是脱敏描述符 | `docs/user/guide/providers.md:13` |
| 配置里只留引用 | `settings.yaml` 里存的是 `apiKeyEnv: <名字>`，永远不是密钥值 | `packages/credentials/credentials/README.md:7` |
| 引用名从哪来 | 页面**从不问你环境变量名**：profile 没有引用时它按 `<ROUTE>_API_KEY` 自己派生 | `packages/client/ui-settings-models/README.md:7` |

派生规则在客户端源码里就一行 `deriveKeyRef()`：`provider.toUpperCase().replace(/[^A-Z0-9]+/g, '_')` 再接 `_API_KEY`（`packages/client/ui-settings-models/src/client/store.ts:69`–`:70`）。所以 route `acme-gateway` 得到 `ACME_GATEWAY_API_KEY`，`minimax-cn` 得到 `MINIMAX_CN_API_KEY`。

`$DSH_HOME` 缺省是 `~/.dsh`（`packages/settings/settings-file/README.md:12`）。这套"配置只带引用、值另存"的分工是有意的：settings 文档可以同步、可以在 UI 里渲染，轮换密钥不动任何配置文件；适配器**每次请求**重新 resolve 一次引用，所以改了 key 下一条请求就用上，不用重启插件（`packages/credentials/credentials/README.md:7`、`:9`）。

页面对你粘进去的 key 有校验：trim 之后必须非空，且每个字符都是可打印 ASCII `[\x21-\x7E]`——这正是 HTTP header 能承载的字符集（`packages/client/ui-settings-models/README.md:13`）。这一半规则在 Host 侧是 `normalizeApiKey()`（`packages/llm/llm/src/api-key.ts:15`、`:36`）。另一半——长得像 `NAME=value` 环境变量整行、或者被引号包住的值会被当作格式错误直接拒——**只跑在浏览器里**，README 给的理由是：解析器上的误判会让环境里那个 key 也一起失效（同上 `:13`）。

**这里最容易踩的**：如果你的 shell 里已经 `export DEEPSEEK_API_KEY=...`，Models 页面**写不进去**。凭据 seam 的规则是：当一个只读来源（进程环境）正在遮蔽这个引用时，`set`/`unset` 直接拒绝，而不是写一个你永远读不到的值（`packages/credentials/credentials/README.md:30`、`packages/credentials/credentials-local/README.md:14`）。想用页面管密钥，先把 shell 里那个变量去掉。

## 2. 加别的厂商：三个入口

| 入口 | 写进哪个 settings 段 | 什么时候用 |
|---|---|---|
| **添加提供方**（Add provider） | `llm-pi-ai:` 下的 `providers.<厂商>` | Anthropic / OpenAI 等 pi-ai 已安装目录里有的厂商，端点、协议、模型列表都由目录供给（`docs/user/guide/providers.md:17`、`packages/llm/llm-pi-ai/README.md:74`） |
| **添加自定义提供方**（Add a custom provider） | 同上，但是一条"手工声明"的 route | 公司网关、自建服务、目录里没有的厂商（`docs/user/guide/providers.md:23`） |
| 直接编辑 `$DSH_HOME/settings.yaml` | 任意段 | 页面只暴露了精选字段，其余全在文件里（`packages/client/ui-settings-models/README.md:33`） |

自定义提供方要填：小写 Provider ID、base URL、API 协议、凭据、至少一个模型（`docs/user/guide/providers.md:23`）。

几个必须知道的约束：

- **Provider ID 是永久的**。请求、已存会话、模型默认值、凭据引用全都用它寻址；改名的唯一办法是新建一个再删旧的（`docs/user/guide/providers.md:27`）。
- **ID 必须以小写字母开头**。它同时是派生凭据引用 `<ROUTE>_API_KEY` 的词干，而引用要求是 POSIX shell 标识符；数字开头能通过页面的所有检查，然后在凭据 seam 上撞一个裸正则报错（`packages/client/ui-settings-models/README.md:21`）。
- **协议只有三种可选**。源码里的表就三条：`openai-completions`、`openai-responses`、`anthropic-messages`（`packages/llm/llm-pi-ai/src/provider.ts:47`–`:51`、`:61`）。写了表外的值会在构造 provider 时抛错，错误信息里直接列出支持的协议（`:177`–`:182`）。页面上的选项是从 namespace 自己的 schema 读的，不会漂移（`packages/client/ui-settings-models/README.md:21`）。
- **Bedrock / Vertex / Azure / Codex 光填 API key 不管用**，它们分别要 AWS 凭据+region、ADC project、`api-version`、OAuth（`docs/user/guide/providers.md:19`）。手工声明这四种协议会被拒绝，因为这套配置形状描述不完它们的鉴权；目录 route 走自己的 provider，仍然能用（`packages/llm/llm-pi-ai/src/provider.ts:35`–`:45`）。
- **获取可用模型**（Fetch available models）问的是表单里**当前显示**的 base URL 和你刚敲进去还没存的 key；返回的是候选清单，选中只改草稿，不落盘（`docs/user/guide/providers.md:29`、`packages/client/ui-settings-models/README.md:19`）。只有目录里没有的 route 才真的走网络，打的是 OpenAI 兼容的 `GET /models`；目录 route 直接从已安装目录回答，一个网络请求都不发（`docs/user/guide/providers.md:29`、`packages/llm/llm-pi-ai/README.md:124`）。端点不提供这个接口就手工录入（`docs/user/guide/providers.md:92`）。

## 3. 两个适配器，一条 seam

dsh 出厂带两个 LLM 适配器，注册在同一个 `ctx.llm` 上：

```
ctx.llm  (packages/llm/llm)
  ├── dsh-llm-deepseek  ── route: deepseek-official   直接 fetch + SSE
  └── dsh-llm-pi-ai     ── route: 任意（openai / anthropic / 你自己的网关）
                            默认 dormant：零 route，直到 settings 给出 profiles
```

- `deepseek-official` 这个 route 名是 `llm-deepseek` 独占的，**故意**跟 pi-ai 目录里的 `deepseek` 不同名，好让一套组合同时挂两条 DeepSeek 路径（`packages/llm/llm-deepseek/README.md:7`）。
- base bundle 里 `llm-pi-ai` 是**空挂**的（dormant）：不给 `providers` 就零 route、picker 里也不多出模型，等 `llm-pi-ai:` 段供出 profile 才实时注册，段空了又摘掉（`packages/bundle/base/cordis.patch.yml:88`–`:96`、`packages/llm/llm-pi-ai/README.md:74`）。Models 页面干的就是这件事。
- 出厂 `llm-deepseek` 条目**不内联任何 key 和端点**，两者都在每次请求时从 `llm-deepseek:` settings 段叠加到条目上解析（`packages/bundle/base/cordis.patch.yml:446`–`:451`）。自定义提供方卡片只能写进 `llm-pi-ai`——那是唯一能用 profile 描述一整个厂商的 namespace；`llm-deepseek` 的 route 是组合事实，页面造不出来（`packages/client/ui-settings-models/README.md:35`）。

## 4. 手写：接一个 OpenAI 兼容网关

`settings.yaml` 里一个手工声明的 route 长这样（照抄 `packages/llm/llm-pi-ai/README.md:49`–`:61` 的 `acme-gateway` 示例，去掉其中的 `compat` 块；顶层段名与缩进对照 `docs/user/guide/providers.md:37`–`:48`）：

```yaml
# $DSH_HOME/settings.yaml
llm-pi-ai:
  providers:
    acme-gateway:
      displayName: Acme Gateway
      apiKeyEnv: ACME_GATEWAY_API_KEY
      api: openai-completions
      baseURL: https://gateway.acme.example/v1
      models:
        - id: acme-large
          name: Acme Large
          contextWindow: 65536
          maxTokens: 4096
```

`cordis.yml` 条目里写的是同一套 schema，只是外面包一层 `config:`——插件把自己的条目配置注册成 settings 段的 `base` 层，用户段叠在上面（`packages/llm/llm-pi-ai/README.md:106`）。写错了不会等到发请求才炸：整份 profile 在 settings 段的 schema 里就解析一遍，不可服务的 profile 在**写入处**被拒（`settings.mutate` 回 `settings-rejected`），并且不会覆盖上一份好配置（`:98`）。

要点与坑：

| 事实 | 出处 |
|---|---|
| `apiKeyEnv` 是**引用**不是值；引用了却解析不到 → 请求以 `MISSING_CREDENTIAL` 失败，而不是拿环境里随便哪个 key 顶上 | `packages/llm/llm-pi-ai/README.md:11` |
| 一条 route 一个凭据，服务它下面所有模型 | `packages/llm/llm-pi-ai/README.md:11` |
| 写了 `models` 就是**整体替换**目录，不是追加：route 要继续服务的模型必须全部列出（只写 `id` 也算） | `packages/llm/llm-pi-ai/README.md:78` |
| 只想改目录里某一个模型 → 用 `modelOverrides`，键是模型 id，其余三十七个照常服务；但它和 `models` 并存、用在手工声明的 route 上、或指向目录里没有的模型，都会被拒而不是被忽略 | `packages/llm/llm-pi-ai/README.md:80` |
| 没被配置的模型 id 在发请求前就以 `UNKNOWN_MODEL` 失败 | `packages/llm/llm-pi-ai/README.md:74` |
| 既没写 entry 尺寸也不在目录里的模型，吃 route 兜底 `defaultContextWindow` 262144 / `defaultMaxTokens` 32768 | `packages/llm/llm-pi-ai/README.md:92` |
| `baseURL` 作用于整条 route 的所有模型；目录 route 不写就各用各的端点 | `packages/llm/llm-pi-ai/README.md:100` |
| **不需要鉴权的本地服务也得给个占位 key**：pi-ai 的 OpenAI 兼容实现仍要求 API key 或 `Authorization` header | `packages/llm/llm-pi-ai/README.md:200` |
| 手写模型默认按纯文本对待；视觉模型要显式加 `input: [text, image]`，页面上没有这个字段 | `docs/user/guide/providers.md:33`、`:35` |
| `headers` 里塞的 `Authorization` **不会被脱敏**，会原样回给任何配置 UI——密钥老实走 `apiKeyEnv` | `packages/llm/llm-pi-ai/README.md:196` |
| route 的目录**永不自刷新**：模型列表只跟你上次编辑一样新 | `packages/llm/llm-pi-ai/README.md:197` |

完整的 19 个可配 profile 字段列在 `packages/llm/llm-pi-ai/README.md:116`。

DeepSeek 侧对应的段是 `llm-deepseek:`，字段有 `apiKeyEnv`（默认 `DEEPSEEK_API_KEY`）、`baseURL`（省略时先看 `$DEEPSEEK_BASE_URL`，再退到公开端点 `https://api.deepseek.com`）、`thinking`、`reasoningEffort`、`maxTokens`、`models` 等（`packages/llm/llm-deepseek/src/index.ts:45`、`:63`–`:80`、`:104`、`:107`）。省略 `models` 时对外通告 `deepseek-v4-flash` 与 `deepseek-v4-pro`，各 1,000,000 上下文窗口（`packages/llm/llm-deepseek/src/index.ts:49`–`:52`、`packages/llm/llm-deepseek/README.md:38`）。

## 5. 凭据存哪：四层，一条诚实的优先级

`.credentials.yaml` 的格式就是一个"引用 → 值"的 YAML 映射，没有 `version`，没有外包一层（`packages/credentials/credentials-local/README.md:31`–`:38`）：

```yaml
# $DSH_HOME/.credentials.yaml
DEEPSEEK_API_KEY: sk-…
OPENAI_API_KEY: sk-…
```

四个来源，从高到低（`packages/credentials/credentials-local/README.md:7`–`:12`）：

```
1. 启动时继承的进程环境        source: env         只读，永远赢
2. $DSH_HOME/.credentials.yaml source: file        可写（set/unset），压两个 .env
3. <启动目录>/.env             source: project-env
4. $DSH_HOME/.env              source: user-env
```

进程环境排第一，是因为 `DEEPSEEK_API_KEY=… dsh`、CI secret、容器 `-e` 是操作员对**这一次运行**的意图；又因为它从内部改不了，所以必须**可见地**只读——`describe()` 报 `writable: false`，`set`/`unset` 直接拒（`packages/credentials/credentials-local/README.md:14`）。

**注意这跟普通配置不是同一条链。** 非密配置的优先级是「本次运行的显式值 > `settings.yaml` > 组合（bundle / 用户 patch / `--patch`） > 本次 shell > `.env` > 默认值」（`.agents/notes/implemented/architecture/2026-08-04-configuration-source-ownership.md:21`–`:28`）；凭据是单独一条（同文件 `:34`–`:39`），差别就在 `settings.yaml` 和组合那两层在凭据里根本不存在。配置只带**引用名**，而引用名本身是普通配置——**引用名走上面那条链，值走下面这条**（同文件 `:41`）。

还有三条硬边界：

- `.env` **不许**设 `DSH_*` 全命名空间、`PATH`、`SHELL`、`NODE_OPTIONS`、`BASH_ENV`、`HOME`、`XDG_*`、代理与 CA 变量——`loadLayeredEnv` 在物化之前就拒，大小写不敏感（`.agents/notes/implemented/architecture/2026-08-04-configuration-source-ownership.md:45`），而且**没有 opt-out**：开关得放在某个能读到的地方，那个地方本身就是洞（同文件 `:47`）。想开这些开关就写进你自己的 shell。
- `.credentials.yaml` 目录 `0700`、文件 `0600`；POSIX 上读到任何 group/other 权限位就在解析内容之前失败，报错里带 `chmod 600` 的修法（`packages/credentials/credentials-local/README.md:46`）。文档格式也严格：非映射根、非 POSIX 标识符的键、非字符串值、空串、重复键、坏 YAML，启动时一律 fail loud，热重载时告警并保留上一份好快照（`:38`）。
- 这个文件**挡的是其它 OS 用户，不是模型**。bash 工具跟 harness 同一个 uid，`workspace-write` 策略管的是写不是读。harness 守住的更窄：它从不把这个文件的解析路径交给模型，也从不把它灌进进程环境（`.env` 才是普通环境层）（`packages/credentials/credentials-local/README.md:54`）。README 自己把这叫"discretion, not a boundary"；要真正隔离，得等 OS keychain provider，现在没有（`:56`）。

## 6. 全局默认模型：出厂值、谁在改、为什么老会话不跟着变

出厂默认写在 base bundle 里（`packages/bundle/base/cordis.patch.yml:63`–`:67`）：

```yaml
- id: agent-default-model
  name: '@deepseek-ai/dsh-agent-default-model'
  config:
    provider: deepseek-official
    model: deepseek-v4-flash
```

这个插件提供 `ctx.agentDefaultModel`，并把 `{provider, model, reasoningEffort?}` 注册成 `agent-default-model` settings 段——组合条目是 base 层，`settings.yaml` 是用户层（`packages/core/agent-default-model/src/index.ts:21`、`:34`、`packages/core/agent-default-model/README.md:7`）。两个方法：`currentSelection()` 读、`saveSelection()` 写（`packages/core/agent-default-model/src/index.ts:88`、`:98`）。

改它的正规入口是**输入框上的模型选择器**（composer's model picker）：选一个模型，同时成为新会话的默认（`docs/user/guide/providers.md:84`、`packages/client/ui-settings-models/README.md:7`）。底层是 `session.selectModel` 应用到本会话之后再调 `saveDefaultModelSelection()`，成功后 `settings.yaml` 里就多一个 `agent-default-model:` 段。**Settings 页面里找不到这个段是故意的**——网关的 Settings 页 allowlist 不暴露它，选择器就是它的编辑器（`.agents/notes/implemented/feature/2026-08-07-default-model-follows-the-picker.md:19`、`:29`）。

为什么老会话不跟着变？因为选择是**分层解析**的（同文件 `:23`）：

```
进程内的会话级选择 > 该会话日志里最近一条 request/header > 当前 Agent 默认值
```

已经发过请求的会话被绑在自己日志里那条持久选择上；空白会话读当前默认值，哪怕它是在你保存偏好之前创建的。

`reasoningEffort` 只在 settings 段里、**不在**插件 config 里：settings 是按字段合并的，组合里配了 effort 就会在用户选了一个不支持它的模型时被继承回来；`saveSelection()` 写的是完整用户段，所以"没写"本身就能清掉旧的 effort（`packages/core/agent-default-model/README.md:7`、`.agents/notes/implemented/feature/2026-08-07-default-model-follows-the-picker.md:17`）。想给整个部署定一个 effort，写到适配器 profile 里（`llm-deepseek` 的 `reasoningEffort`，或 pi-ai profile 的 `reasoning`）。

**没有 `--model` 这类 CLI flag。** 启动器自己的全部选项就四个：`--profile`、`--patch`、`--dump-config`、`--dump-default-config`，外加 `web` 和 `plugin` 两个子命令（`apps/cli/src/args.ts:130`–`:134`、`:156`–`:175`）。headless 也不靠 flag 选模型：它 inject `agentDefaultModel`，直接读 `currentSelection()`（`packages/bundle/headless/src/index.ts:28`、`:101`、`:106`）——跟 Web 选择器写的是同一个默认值。

真正由组合写死模型的是另一处：`agent-loop` 的 `agents[]`，那是**在启动时就创建好的 agent**。base bundle 把它留空（`packages/bundle/base/cordis.patch.yml:434`–`:439`），字段形状见 `packages/core/agent-loop/README.md:38`–`:49`，一份填满的真实示例（`agents: [{id: main, provider: …, model: …}]`）在 `docs/user/develop/practice/llm-adapter.md:135`–`:142`。模型调用要求 `provider` 和 `model` **成对**出现；缺失的那一对可以由 `agent/request` 在派发前补上（`packages/core/agent-loop/README.md:52`）。

## 7. 按用途分开配：主循环 / 标题 / 压缩 / 子 agent

能分开，但**四个用途分别归四个不同的插件管**，没有一个统一的"模型用途表"。`GenerateOptions.purpose` 这个字段只有两个值 `'compaction' | 'session-title'`，而且它是给适配器做模型不可见的传输元数据用的，不是选路开关（`packages/llm/llm/src/types.ts:350`–`:355`）。

| 用途 | 配在哪 | 字段 | 不配会怎样 |
|---|---|---|---|
| 主循环 | `agent-default-model` 段 / 模型选择器；组合启动时创建的 agent 用 `agent-loop.agents[]` | `provider` + `model` | 用 base bundle 的 `deepseek-official` / `deepseek-v4-flash` |
| 会话标题 | `session-title-first-prompt-llm`（或 `-all-prompts-llm`）条目 config | `provider` + `model`，**要么都给要么都不给** | 沿用当前会话日志里 `request/header` 记的那条 route（`packages/session/session-title-llm/README.md:11`、`:26`） |
| 压缩摘要 | `compaction-basic` 条目 config | `summarizationProvider` + `summarizationModel` + `maxTokens` | 空对儿 → 先取最近一条已记录请求的 target，再取 `AgentOptions` 的对儿（`packages/compaction/compaction-basic/README.md:35`–`:37`） |
| 子 agent | `tool-subagent` 条目 config | `agentOptions.provider` / `.model` / `.maxTokens`（`packages/subagent/tool-subagent/README.md:25`） | 继承父 agent 的模型（`packages/subagent/subagent-spawn-in-process/README.md:9`） |

会话标题的真实例子（把标题打到 flash 上，`examples/acp-agent/session-title.cordis.yml:10`–`:19`）：

```yaml
- id: session-title-provider
  name: '@deepseek-ai/dsh-session-title-first-prompt-llm'
  config:
    targetWords: 5
    targetCjkCharacters: 10
    maxInputBytes: 4096
    maxOutputTokens: 32
    timeoutMs: 5000
    provider: deepseek-official
    model: deepseek-v4-flash
```

在原文件里这个条目嵌在 `cordis-plugin-include` 的 `patches: - insert:` 下面（`:4`–`:9`）；你自己的 `cordis.patch.yml` 里直接写成一条 `insert` 操作即可（见第 02 章）。

压缩换个便宜模型：条目本体的真实形状抄自 `examples/headless-agent/cordis.yml:76`–`:82`（那里配的是 `thresholdRatio` / `retainRatio` / `maxTokens` / `compactionRetries`），摘要 route 那两个字段按 `packages/compaction/compaction-basic/README.md:35`–`:37` 加上去；以 patch 覆盖既有条目的写法见 `examples/headless-agent/compaction.cordis.snapshot.yml:10`–`:15`。

```yaml
- id: compaction-basic
  name: '@deepseek-ai/dsh-compaction-basic'
  config:
    summarizationProvider: deepseek-official
    summarizationModel: deepseek-v4-flash
    maxTokens: 8192
```

子 agent 同理：在 base bundle 已有的 `tool-subagent` 条目（`packages/bundle/base/cordis.patch.yml:313`–`:318`）上补一个 `agentOptions: {provider, model}`。注意 patch 是**整体替换** `config`，原有的 `provider` / `toolName` / `backgroundMode` 三行必须一起重写（见第 02 章）。

**这四类里只有主循环那一格能热改。** settings 段有两条注册路径：`installSettingsSection()` 助手，和它底下的 `ctx.settings.register()`。两条都 grep 过（`packages/**/src/`），一共 13 个包注册了 settings 段——走助手的 8 个是 `agent-default-model`、`agent-loop`、`llm-deepseek`、`llm-pi-ai`、`permission-presets`、`bash-local`、`pwsh-local`、`web-search-deepseek`；直接调 `register()` 的 5 个是 `agent-presets`（源码里专门写了一段为什么不用助手，`packages/preset/agent-presets/src/index.ts:136`–`:146`）、`client/locale`、`client/ui-conversation`、`client/ui-settings-general`、`client/ui-theme`。

`compaction-basic`、`session-title-*`、`tool-subagent` 一个都不在里面——它们只能通过组合层改（`cordis.patch.yml` / `--patch`，见第 02 章），改完要重启。而且 `agent-loop` 注册的段里只有 `maxParallelToolCalls` 一个字段，`agents` 被**刻意排除**在外：它在服务启动时只消费一次，存进 settings 只会看起来生效（`packages/core/agent-loop/README.md:52`）。所以真正能热改模型的只有 `agent-default-model` 那一格，也就是模型选择器。

另外两条值得知道：

- 一个 `tool-subagent` 实例的子 agent 策略是**钉死**的：换模型、换 persona、换工具过滤、换深度上限，都得再挂一个改名的实例（`packages/subagent/tool-subagent/README.md:82`）。base bundle 已经用这个办法挂了两个工具：`subagent`（spawn，continuable）和 `subagent_fork`（fork，one-shot）（`packages/bundle/base/cordis.patch.yml:313`–`:329`）。
- 标题请求带 `purpose: 'session-title'`，DeepSeek 适配器会把它映射成"关闭思考"，好把那点输出预算全留给可见标题文本（`packages/llm/llm-deepseek/README.md:46`）。压缩请求带 `purpose: 'compaction'`，额外发一个 `x-deepseek-harness-compact: 1` 头（`packages/llm/llm-deepseek/README.md:63`）。

## 8. 进阶：自定义 LLM 适配器的最小形状

厂商实在接不上（协议不是那三种之一、鉴权方式特殊），就自己写一个适配器。它是一个普通 Cordis 插件，唯一必须实现的是 `stream()`（`packages/llm/llm/src/index.ts:180`、`:228`–`:232`）。下面是 `docs/user/develop/practice/llm-adapter.md:13`–`:50` 的完整最小实现，只删掉了原文 `stream()` 体内的三行步骤注释：

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'
import { LlmAdapter, type GenerateOptions, type StreamChunk } from '@deepseek-ai/dsh-llm'

class MyAdapter extends LlmAdapter {
  private apiKey: string

  constructor(apiKey: string) {
    super()
    this.apiKey = apiKey
  }

  async *stream(options: GenerateOptions): AsyncIterable<StreamChunk> {
  }
}

export interface Config {
  apiKey: string
  providers: string[]
}

export const Config: Schema<Config> = Schema.object({
  apiKey: Schema.string().required(),
  providers: Schema.array(Schema.string()).required(),
})

export const name = 'my-llm-adapter'
export const inject = ['llm']

export function apply(ctx: Context, config: Config) {
  const adapter = new MyAdapter(config.apiKey)
  ctx.llm.registerAdapter(config.providers, adapter)
}
```

`stream()` 体内要干的三件事，原文写在注释里（`:27`–`:29`）：把 `options.messages` 转成厂商格式、调用流式 API、把响应转回 `StreamChunk`。挂载到 `cordis.yml` 的写法照 `:127`–`:142` 抄。`registerAdapter(providers, adapter)` 的第一个参数是这个适配器承接的 route 列表；请求用 `GenerateOptions.provider` 选适配器、`GenerateOptions.model` 直接透传模型 id，不需要在生命周期里注册模型（`docs/user/develop/practice/llm-adapter.md:123`、`packages/llm/llm/src/index.ts:338`）。可选覆写四个方法：`providerInfo()`、`providerRetryPolicy()`、`listModels()`、`resolveModel()`（`packages/llm/llm/src/index.ts:186`、`:195`、`:206`、`:219`）。

往下就三处：`docs/user/develop/practice/llm-adapter.md` 的 `StreamChunk` 协议逐条（`:52`–`:109`）、`GenerateOptions` 说明（`:113`–`:115`）、错误处理与"每个 HTTP 请求都必须合并 `attributionHeaders()` 并转发 `options.signal`"（`:155`）；然后对着读 `packages/llm/llm-deepseek/`（直接 `fetch` + SSE）和 `packages/llm/llm-pi-ai/`（基于第三方 SDK）——同一份契约的两种内核实现（`docs/user/develop/practice/llm-adapter.md:151`）。

> 想知道这一点上 Pi / Codex / LangChain 怎么做，见 [五个 agent 系统源码解剖](../2026-08_五个agent系统源码解剖/00-总览与阅读指南.md)。
