# 读源码写文档门禁

本仓库的文档只有一个目标：**让读者读明白这个事、这个机制、这个策略——从人的阅读角度，而不是让读者去啃一堆代码说明。**

两个必读范本（动笔前先通读，不许跳过）：

- 文风范本：`2026-08_DeepSeekHarness上手教程/18-沙箱审批与权限.md` 的"四个画面"部分——机制怎么用画面和比喻讲。
- 格式范本：`2026-08_DeepSeekHarness上手教程/10-事件系统.md` 全文——脚注、附录、正文怎么组织。

## 一、文风：机制画面法（费曼式）

叙事骨架是"读者的误解怎么被纠正"，不是"代码里有什么"。七个手法：

1. **误解开场**。全章和关键小节先立读者最可能有的误解，一句"不是的"拆掉再开讲。没有天然误解就用读者此刻最想问的问题开场。禁止"本章将介绍…"式开场。
2. **概念倒叙**。现象在前，术语在后当标签："它想删文件，唯一的办法是喊一声……这一声喊叫有个名字，叫系统调用。"禁止"X 是指……"先甩定义。
3. **画面骨架**。每个大节回答一个读者真实会问的问题，沉淀一条不变量（粗体立柱，一句一条）。小节标题用断言或问题（"锁是进程自己给自己上的"），不用名词短语（"沙箱机制概述"）。
4. **比喻必须能推导结论**。只在比喻能直接推出本章某个反直觉结论时才用（范本：从"清单只写了禁写"推出"read-only 还能读 SSH 私钥"）。推不出结论的装饰性比喻一律删。宁缺毋滥。
5. **反直觉点当靶心**。原材料里最劝退的点不许绕开，要变成某个画面的"验收题"正面回收。
6. **代码是证据不是主线**。讲解处若必须出示代码，用前后对照（改写前 vs 改写后、输入 vs 输出），禁止逐行讲解。
7. **串珠结尾**。结尾把全章结论逐条从前面的画面重新推一遍（"之所以 X，是因为画面 Y 里的 Z"），供读者自检；最后一句话总结收束。

## 二、格式：三条硬规则

1. **正文散文里一处 `file:line` 都不许出现。** 所有出处坐标收进文末 `## 出处` 节做 GFM 脚注（`[^1]`），正文只留角标，角标打在被支撑的论断句末。表格不设"出处"列。文件开头的引用行注明"出处收在文末脚注"。
2. **非代码块里不出现代码。** 代码表达式、调用片段、文件路径不进散文。事件名/API 名/命令名这类专有名词可保留反引号，但压密度：反复出现时改用中文指代。英文报错/文档原话按引文保留，坐标进脚注。
3. **正文少堆代码，机制用人话讲。** 带行号标注的伪代码改成编号列表或短段落；mermaid 图是主力载体；可照抄的完整代码（插件全文、配置模板）收进文末 `## 附录：可以照抄的模板`，正文一句"照抄附录 X"锚点链接过去。**实操章例外**：读者按顺序敲的命令、预期输出、作为步骤本体的短配置片段留正文原位——那是读者要做的事，不是要读的说明。演示证据（日志样本、报错原文）也留正文。

## 三、章节结构模板

```text
# NN · 断言式标题
> 基于 <仓库> <版本>（commit <hash>），<绝对日期> 核对。出处收在文末脚注，可照抄代码收在附录。
误解开场段
## 画面/问题式大节 ×N（每节：误解或提问 → 机制人话 → mermaid/表格 → 粗体柱子 → 角标）
## 把这一章串起来（串珠结尾）
## 附录：可以照抄的模板（A/B/C…，代码块首行注释可标坐标）
## 出处（[^1]: 说明 + 坐标；同文件后续坐标用 :N 短形式）
```

仓库既有约定同时生效：绝对日期；一手核实与"第三方来源、未经确认"标注跟着论断走；中文行文、术语保英文；新增/改名/删除文档必须同步 README.md 索引。

## 四、交付前机器门禁（四项全过才算完成）

对每个改动的文档跑，任何一项不过就修完再交：

```bash
F=<文件路径>

# 1. 正文清洁度：必须输出 0
sed -n '1,/^## 出处/p' "$F" | sed '/^```/,/^```/d' | grep -cE '\.(ts|tsx|md|yml|yaml|json|sh|mjs|go|py):[0-9]+'

# 2. 围栏配平：必须是偶数
grep -c '^```' "$F"

# 3. 脚注配对：两个数字必须相等
grep -oE '\[\^[0-9]+\]' "$F" | sort -u | wc -l
grep -cE '^\[\^[0-9]+\]:' "$F"

# 4. 改写场景加测事实不丢：与改写前留底比对，唯一允许的差异是可解释的区间合并
grep -oE ':[0-9]+(-[0-9]+)?' 留底文件 | sort -u > /tmp/old.txt
grep -oE ':[0-9]+(-[0-9]+)?' "$F"     | sort -u > /tmp/new.txt
comm -23 /tmp/old.txt /tmp/new.txt   # 每一条输出都必须能说明"被哪个区间覆盖"，说明不了=丢失
```

改写既有文档必须先 `cp` 留底再动笔。

## 五、交付前人工自检清单

- [ ] 开场是误解或真问题，不是"本章介绍"
- [ ] 每个大节有粗体不变量柱子
- [ ] 每个比喻都能推出至少一条反直觉结论，推不出的已删
- [ ] 原材料里最劝退的点被当验收题正面回收了，没绕开
- [ ] 结尾是串珠自检，不是干巴总结
- [ ] 没有"本章将介绍/综上所述/接下来我们来看"过场套话
- [ ] "未确认/第三方来源/没跑过"标注原样跟着对应论断
- [ ] README.md 索引已同步（若有增删改名）

委托子代理写作时，把本文件路径和两个范本路径写进提示词，并要求子代理在最终回复里报告四项门禁的数字结果。
