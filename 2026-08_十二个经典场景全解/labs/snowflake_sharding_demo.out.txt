二、写入路径：一条订单是怎么落到具体某张表的
==================================================================
场景：user_id = 10086 下单 99 元。集群 = 2 库 × 16 表 = 32 分片

Step 1｜先算基因
    gene = user_id % 32 = 10086 % 32 = 6
    6 的二进制 = 00110   ← 这 5 位待会儿要塞进 ID 的最低位

Step 2｜生成带基因的 order_id（位分配：41 时间戳 / 6 机器 / 11 序列 / 5 基因）

    order_id = 78373186106228742

    0        00000010001011001101111111111110101110111  000111  00000000000  00110
    ↑        ↑                                         ↑       ↑            ↑
    符号1位  时间戳41位                                 机器6位 序列11位     ★基因5位

    反解: 时间=2026-08-05 14:27:03.671  机器=7  序列=0  基因=6 (00110)
    ✅ 基因位 = 6，和 user_id % 32 = 6 完全一致

Step 3｜中间件算路由
    slot = order_id % 32 = 6
    库   = slot // 16 = 0  →  ds_0
    表   = slot %  16 = 6  →  t_order_06

Step 4｜SQL 被改写
  ┌──────────────────────────────────────────────────────────────┐
  │ 逻辑 SQL（你写的）:                                          │
  │     INSERT INTO t_order (id, user_id, amount)                │
  │     VALUES (78373186106228742, 10086, 99.00)                │
  ├──────────────────────────────────────────────────────────────┤
  │ 真实 SQL（中间件改写后真正发给 MySQL 的）:                   │
  │     INSERT INTO ds_0.t_order_06 (id, user_id, amount)        │
  │     VALUES (78373186106228742, 10086, 99.00)                │
  └──────────────────────────────────────────────────────────────┘

  📍 数据最终落在:  ds_0.t_order_06

三、两条读取路径
==================================================================
路径 A：点开「我的订单」

    SQL:  SELECT * FROM t_order WHERE user_id = 10086
    路由:  slot = 10086 % 32 = 6  →  ds_0.t_order_06
    真实:  SELECT * FROM ds_0.t_order_06 WHERE user_id = 10086
    🎯 只访问 1 个分片（共 32 个）

路径 B：点开订单详情页（关键）

    SQL:  SELECT * FROM t_order WHERE id = 78373186106228742

    ⚠️  这次 WHERE 里根本没有 user_id！

    但 order_id 的低 5 位 = 00110 = 6
    slot = order_id % 32 = 6  →  ds_0.t_order_06
    真实:  SELECT * FROM ds_0.t_order_06 WHERE id = 78373186106228742
    🎯 也只访问 1 个分片！

  ┌──────────────────────────────────────────────────────────────┐
  │ 恒等式验证                                                   │
  │     user_id  % 32 = 6                                        │
  │     order_id % 32 = 6                                        │
  │     两者相等？ True   →  同一个分片，一次命中               │
  └──────────────────────────────────────────────────────────────┘

四、对照组：不用基因法会怎样
==================================================================
用普通雪花生成的 order_id，它的低 5 位来自序列号，和 user_id 毫无关系：

    普通雪花: order_id = 78373186105798662
    低 5 位 = 00110 = 6

    user_id 10086 的数据其实在 ds_0.t_order_06
    但 order_id % 32 = 6 → 算出 ds_0.t_order_06

所以按 order_id 查详情时，只能全分片广播：
